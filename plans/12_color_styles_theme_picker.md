## Что изменилось в дизайне

1. **Режим темы** — группа M3E-кнопок с иконками (`light_mode` / `dark_mode` /
   `brightness_auto`) вместо сегментированного переключателя с подписями.
   Выбранная кнопка раздвигается и из «пилюли» становится скруглённым квадратом.
   Название текущего режима — справа от подзаголовка «Тема».
   **Уточнение пользователя:** выбранная кнопка занимает половину ряда, две другие
   делят вторую половину; зазоры между кнопками вычитаются заранее.
2. **Стиль** — три карточки с мини-превью: «Цветной», «Монохром», «AMOLED».
3. **Акцентный цвет** — слайдер есть во всех стилях. Справа от подзаголовка —
   квадратик текущего акцента, под слайдером — подсказка, своя для цветного стиля
   и для монохрома.
4. **Слайдер акцента** похож на общий слайдер приложения: вместо круглой ручки —
   вертикальная полоса 6×36 с обводкой 3 px.
   **Уточнение пользователя:** обводка ручки — ровно цвет контейнера, без тени,
   чтобы ручка «вырезала» часть трека, как у общего слайдера.

## Палитры

Источник значений — `m3.css` (`.m3-mono-dark`, `.m3-amoled`, `.m3-mono-light`).

- **Цветной** — как сейчас: `ColorScheme.fromSeed` по оттенку из слайдера,
  в светлой теме — нейтральные поверхности.
- **Монохром** — шкала серого и один акцент. Акцент (`primary`, `onPrimary`,
  `inversePrimary`) берётся из `ColorScheme.fromSeed` по тому же оттенку, всё
  остальное — фиксированные серые. Контейнеры, карточки групп, навбар, чипы,
  тональные кнопки — серые. `error` остаётся красным. `success` / `warning` /
  `info` сведены к нейтральным тонам. FAB — на акценте (в цветном — на
  `primaryContainer`): в UI-ките монохрома «акцент только на главном: filled-кнопка,
  FAB, переключатель, прогресс».
- **AMOLED** — тот же монохром, но фон и нижние поверхности чисто чёрные. Стиль
  меняет только тёмную тему, в светлой работает как монохром.

## Архитектура

Каждая палитра — отдельный класс, общий код — в базовом классе. Новая палитра =
новый класс + значение в `AppColorStyle` + ветка в `switch` (exhaustive switch не
даст забыть ветку).

```
lib/uikit/theme/
  app_colors.dart                  ThemeExtension: цвета сверх ColorScheme
  app_theme.dart                   ThemeData из палитры: только темы компонентов
  app_theme_scope.dart             стиль из настроек → палитра → ThemeData
  palette/
    app_palette.dart               abstract AppPalette: colorScheme() + appColors()
    seed_palette.dart              «Цветной»
    monochrome_palette.dart        «Монохром»
    amoled_palette.dart            «AMOLED» (наследник монохрома)
```

- `AppPalette.colorScheme({brightness, accent})` → `ColorScheme` (все роли M3).
- `AppPalette.appColors(ColorScheme)` → `AppColors`: `success`, `onSuccess`,
  `warning`, `info`, `fab`, `onFab`, шкала точности `accuracyHigh/Mid/Low`.
- `AppColors` — `ThemeExtension` с `lerp`, чтобы смена темы анимировалась, а не
  прыгала. Доступ — `AppColors.of(context)` / `theme.appColors`.
- Геттеры `success` / `warning` / `info` / `onSuccess` уходят из расширения
  `ColorScheme` в `AppColors` (≈25 мест). Остальные легаси-геттеры (`card`,
  `muted`, `border`…) — роли M3, они уже следуют за палитрой.
- `question_stats_view._accuracyColor` — убрать хардкод ярких цветов светлой темы,
  взять шкалу из `AppColors` (в монохроме зелёный был бы чужим).
- `M3EScope` — строить `M3EColorScheme` из `ColorScheme` и `AppColors` приложения,
  а не из `primary` как seed: иначе M3E-виджеты в монохроме окрасятся.
- Старый неиспользуемый интерфейс `AppColors` (`AppColorsLight/Dark`) в
  `app_colors.dart` заменяется на `ThemeExtension`.

## UI

- `lib/uikit/buttons/app_toggle_button_group.dart` — `AppToggleButtonGroup`:
  ряд `M3EButton` с `isSelected` (форма «пилюля → скруглённый квадрат» и нажатие —
  из пакета). Ширины считает сама: выбранная — половина ряда за вычетом зазоров,
  остальные делят остаток. Ширина анимируется (`AppMotion.spring`, `medium`),
  сумма ширин в любой момент равна ширине ряда. `M3EButtonGroup` не подходит:
  при фиксированной `width` у действия он не анимирует ширину.
  Цвета по дизайну: выбранная — `primary`, остальные — `surfaceContainerHighest`.
- `feature/settings/.../widget/color_style_picker.dart` — карточки стилей.
  Превью строится из тёмной палитры самого стиля с текущим акцентом: фон,
  три полосы из пула карточек групп, точка акцента. Новая палитра получит
  превью без доработок.
- `HueSlider` — ручка-полоса 6×36, обводка `cutoutColor` (по умолчанию
  `surfaceContainer` — подложка карточки), без тени; `thumbColor` — в цветном
  стиле цвет под ручкой, в монохроме — `primary`.
- Строки — в ARB (`settingsAppearance*`, `settingsTheme*`, `settingsStyle*`,
  `settingsAccentHint*`). `profileAccentColorTitle` → «Акцентный цвет».

## Рывки при смене темы (2026-10-04)

Профиль на Nothing Phone (3), 120 Гц: build 12.1 мс + paint 5.1 мс на кадр при
бюджете 8.3 мс; растеризация 1.9 мс. На Pixel и эмуляторе (60 Гц) укладывается.

Причина: `MaterialApp` ~200 мс интерполирует `ThemeData` и в каждом кадре
пересобирает всё, что зависит от темы, — включая невидимые экраны: профиль под
настройками, неактивные табы. Смена стиля стоит столько же, просто при ней нет
движущейся кнопки и переход тёмная→тёмная почти не виден.

Что сделано:
- `MaterialApp` применяет тему за кадр (`AnimationStyle.noAnimation`).
- `AnimatedThemeScope` — плавный переход только там, где его видно: экран
  настроек и нижняя панель навигации.
- `HiddenThemeFreeze` — экраны под текущим маршрутом (через
  `pageTransitionsTheme`) и неактивный таб «Статистика» держат прежнюю тему и
  обновляются один раз, когда снова видны. Признак скрытости — выключенный
  `TickerMode`. Тема Cupertino замораживается вместе с Material: `Theme.of`
  подписан и на неё.
- Превью стилей считают `ColorScheme.fromSeed` в родителе, а не в карточках,
  которые пересобирались каждый кадр анимации.

Стенд (тестовое окружение, JIT, без растеризации; настройки поверх тяжёлого
экрана), кадр анимации темы: было ~4370 пересборок / ~35 мс, стало ~546 / 6–8 мс.
Первый кадр (само переключение) ~15 мс. На устройстве не перепроверено.
