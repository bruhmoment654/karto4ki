# План: экран результата «Разбор» (вариант C) и «Продолжить тест» (вариант A)

> Источник дизайна: проект Claude Design «karto4ki»,
> https://claude.ai/design/p/a1a78f7b-9e47-4933-8bcb-a0de15ec7a43?file=karto4ki.html
> Секции «Результаты теста» (`C · Разбор…`, включая первое прохождение) и
> «Главная — продолжить тест». Файлы: `screens-result.jsx` (`ResultC`), `screens-resume.jsx`
> (`ResumeCard`), `screens-home.jsx`.
> Дата: 2026-10-03. Ветка: `design-fixes`.

## Статус (2026-10-03)

Этапы 1–5 реализованы, анализатор чистый, 271 тест проходит. Падают 5 голденов
`test_detail_view_golden_test` — эталоны сняты в старой светлой теме до редизайна,
к этой задаче не относятся.

Отступления от плана и макета:
- чип дельты переносится на вторую строку вместо обрезки: на 360–390 px колонка
  рядом с кольцом около 200 px;
- фильтр-чипы — горизонтальная лента: четыре M3-чипа в строку не помещаются;
- в кольце подпись «N / M», как в текущем варианте B (в макете — «N из M»);
- восстановленная завершённая сессия теперь записывается как прохождение и
  стирается — раньше она оставалась на главной как «Продолжить N из N».

Не проверено: ручной прогон на устройстве (первое прохождение → повтор →
повтор с подмешиванием; продолжение сессии, сохранённой до обновления).

## 1. Экран результата C

### 1.1. Что на экране

Экран прокручивается, кнопки закреплены снизу (над навбаром).

| Блок | Повторное прохождение | Первое прохождение |
|---|---|---|
| Шапка | `×`, «Результат» (без share) | так же |
| Сводка | кольцо 132 px без иконки (`%` + «N из M»), заголовок по порогу, чип дельты «+20% к прошлому разу» (↑ success / ↓ error) | вместо дельты — чип «Первое прохождение» (иконка `flag`, `secondaryContainer`) |
| Динамика | карточка «Последние прохождения»: столбики `%` последних 5 попыток, даты `dd.MM`, у текущей — «сейчас», счётчик «5 из 12» | карточка «Динамика появится позже / Пройдите тест ещё раз — сравним результат с этим прохождением» и `ShapePlate` (7 углов, иконка `timeline`) |
| Фильтры | Все / Ошибки / Исправил / Забыл (с количеством) | Все / Ошибки |
| Строка вопроса | ✓/✗, вопрос, ответ; справа точки последних ≤5 ответов (свежая крупнее) и метка тренда | ✓/✗, вопрос, ответ; справа «Знаю» / «Не знаю» |
| Кнопки | «Пройти ещё раз» (tonal) + «Готово» (filled) | так же |

Заголовок по порогу (из макета): ≥90% — «Отличный результат!», ≥60% — «Хорошая работа!»,
ниже — «Есть над чем поработать». Сейчас заголовок один на все случаи
(`tinderTestResultsTitle`).

Кнопки: в макете слева стоит «Повторить ошибки». Её не делаем, а на это место ставим
существующую «Пройти ещё раз» (`onRestartPressed`). Это единственное отступление
от макета.

### 1.2. Каких данных не хватает

Текущая сессия (`TestSession`: карточки + ответы) закрывает кольцо, заголовок,
список с ✓/✗ и фильтр «Ошибки», то есть весь экран первого прохождения.

Для повторного прохождения не хватает **истории прохождений теста**. Сейчас её нет
нигде: `ActiveSession` после завершения стирается, а `question_stats` хранит только
агрегаты, без последовательности ответов (`streak` — сумма ±1). Её нужно начать
хранить, история копится с релиза.

Значит, после релиза у каждого теста первый проход покажет экран «первое
прохождение» даже при богатой старой статистике. Это ожидаемо.

## 2. Модель данных

Две локальные таблицы в `AppDatabase`: `schemaVersion` 10 → 11, в `onUpgrade` —
`if (from < 11) m.createTable(...)` для обеих таблиц и индексов.

```sql
-- Завершённые прохождения тестов. Только локально, в синк не входит.
CREATE TABLE test_attempts (
  id TEXT NOT NULL PRIMARY KEY,      -- детерминированный: testId + startedAt
  test_id TEXT NOT NULL,
  started_at DATETIME NOT NULL,
  completed_at DATETIME NOT NULL,
  total INTEGER NOT NULL,
  correct INTEGER NOT NULL,
  mixup BOOLEAN NOT NULL,
  swap_sides BOOLEAN NOT NULL
) AS TestAttemptDatabaseDto;

CREATE INDEX IF NOT EXISTS idx_test_attempts_test
  ON test_attempts(test_id, completed_at);

-- Ответы внутри прохождения.
CREATE TABLE test_attempt_answers (
  id INTEGER NOT NULL PRIMARY KEY AUTOINCREMENT,
  attempt_id TEXT NOT NULL,
  question_key TEXT NOT NULL,
  is_correct BOOLEAN NOT NULL
) AS TestAttemptAnswerDatabaseDto;

CREATE INDEX IF NOT EXISTS idx_test_attempt_answers_attempt
  ON test_attempt_answers(attempt_id);
```

- **Внешние ключи.** `PRAGMA foreign_keys` в `AppDatabase` не включён, а тесты
  удаляются мягко (`tests.deleted_at`), поэтому `REFERENCES … ON DELETE CASCADE` ничего
  бы не дал. Попытки удалённого теста просто лежат: их некому показать, объём мизерный.
- **Детерминированный id** нужен для идемпотентности. Если приложение убили между
  `completed` и `_clearSession`, при следующем открытии восстановится уже завершённая
  сессия ([tinder_test_bloc.dart:159](../lib/feature/tinder_test/domain/bloc/tinder_test_bloc.dart#L159)).
  Запись делаем через `insertOrIgnore`, а при сборке сводки текущую попытку
  исключаем по id.
- **Ключ вопроса** — `question_key`, как в `question_stats`. Он переживает переимпорт
  карточек, у которого другие `card_id`.
- **Перевёрнутые стороны.** При `swapSides` ключ считается от перевёрнутой карточки
  (так уже работает статистика), поэтому у «прямого» и «обратного» направлений
  точки и тренды раздельные. В графике попыток оба направления идут в одной серии.
- **Подмешанные вопросы** получают историю только из прохождений этого теста, где
  их подмешивали. Обычно это мало точек: показываются как «новый в тесте»
  (см. 2.2).
- `question_stats`, `answer_events_outbox` и `saveSessionResults` не трогаем. Попытка
  пишется отдельно и с ними не гоняется.

### 2.1. Домен

```dart
@freezed
sealed class TestAttemptEntity { id, testId, startedAt, completedAt, total, correct }

enum QuestionTrend { firstCorrect, fixed, forgot, repeatedMistake, stable }

@freezed
sealed class QuestionResult {
  CardEntity card;
  bool isCorrect;
  List<bool> history;     // ≤5 ответов в этом тесте, последний — текущий
  QuestionTrend? trend;   // null — вопрос новый в этом тесте
}

@freezed
sealed class AttemptSummary {
  List<TestAttemptEntity> recent;  // ≤5 последних, последняя — текущая
  int totalAttempts;               // «5 из 12»
  List<QuestionResult> items;
  bool get isFirst => recent.length == 1;
  int? get delta;                  // % текущей − % предыдущей; null для первой
}
```

Репозиторий — `ITestAttemptRepository.recordAttempt(TestSession session, {mixup, swapSides})
→ RequestOperation<AttemptSummary>`. Вызов в транзакции:

1. `insertOrIgnore` попытки и её ответов.
2. Взять последние 5 попыток теста по `completed_at` и общее их число.
3. Взять ответы всех **предыдущих** попыток теста по ключам текущей сессии.
   Объём небольшой (50 попыток × 30 карточек = 1500 строк), тренды и точки
   считаем в Dart.

### 2.2. Правила тренда (в рамках теста)

`prev` — предыдущие ответы на этот вопрос в прохождениях этого теста, от старых к новым.

| Условие | Тренд / вид строки |
|---|---|
| `prev` пуст (первое прохождение или вопрос новый в тесте) | `trend = null`, строка как в первом прохождении: «Знаю» / «Не знаю» |
| ✓ и в `prev` нет ни одного ✓ | `firstCorrect` — «Впервые верно» |
| ✓, последний из `prev` — ✗ | `fixed` — «Исправил» |
| ✗, последний из `prev` — ✓ | `forgot` — «Забыл» |
| ✗, последний из `prev` — ✗ | `repeatedMistake` — «Снова ошибка» |
| ✓, последний из `prev` — ✓ | `stable` — «Стабильно» |

«Впервые верно» проверяем по **всей** истории в тесте, а не по 4 видимым точкам, как
в макете: иначе вопрос, отвеченный верно 6 прохождений назад, получил бы неверную метку.

Фильтры «Исправил» / «Забыл» — это строки с `fixed` / `forgot`. Счётчики считаются
по `items`.

## 3. Bloc и flow

1. `TinderTestState.completed({session, AttemptSummary? summary})`. `completed` эмитим
   сразу, как сейчас: кольцо начинает анимацию. Сводку — вторым эмитом, когда
   `recordAttempt` вернётся.
2. Пока `summary == null`, показываем сводку без чипа, без карточки динамики и без
   правой колонки в строках. Когда сводка приходит, блоки появляются через
   `AppAnimatedSize` / `AppAnimatedSwitcher`. Если `recordAttempt` упал, логируем,
   а экран остаётся в виде первого прохождения, только без чипа «Первое
   прохождение».
3. В `_handleSwipe` / `_onCompleted`: `_saveStats` → `_recordAttempt` → `_clearSession`.
   Порядок важен: сессию стираем только после записи попытки.
4. Восстановление завершённой сессии ([tinder_test_bloc.dart:159](../lib/feature/tinder_test/domain/bloc/tinder_test_bloc.dart#L159))
   тоже вызывает `_recordAttempt`. Запись идемпотентна, а сводка нужна экрану.
5. «Пройти ещё раз» работает как сейчас (`TinderTestEvent.restarted`). Новое
   прохождение по завершении — новая попытка.
6. Незавершённые (брошенные) сессии попытками не считаются.

## 5. «Продолжить тест», вариант A

### 5.1. Карточка

[active_session_card.dart](../lib/feature/groups_list/presentation/widget/active_session_card.dart)
переписываем по `ResumeCard`:

- контейнер `surfaceContainerHigh`, радиус XL, отступы `16 / 8 / 16 / 20`;
- слева колонка: «Продолжить тест» (`labelLarge`, `primary`), название теста
  (`titleLarge` w600, ellipsis), группа (`bodyMedium`, `onSurfaceVariant`, скрыта,
  если группы нет); справа `IconButton(close)`;
- `AppLinearProgress(isWavy: true, value: done / total)`;
- строка: «N из M карточек» + `FilledButton.icon(play_arrow, «Продолжить»)`;
- «0 из N» — тот же вид, прогресс 0;
- тап по всей карточке тоже продолжает тест (как сейчас): так больше область нажатия.

Место и анимация появления остаются прежними (`_ActiveSessionSliver` над списком групп).

### 5.2. Группа в сессии

Сейчас в сессии группы нет, а тест может лежать в нескольких группах.

- Добавить `groupId` (nullable) в цепочку
  `GroupDetailScreen.onTestTapped → TestDetailRoute → TinderTestRoute →
  ActiveSessionLaunchParams` и в `LaunchParamsDto` (nullable поле — старые
  сохранённые сессии читаются без миграции).
- При продолжении `groupId` передаётся обратно в `TinderTestRoute`
  ([groups_list_screen.dart:61](../lib/feature/groups_list/presentation/groups_list_screen.dart#L61)).
- Название берём при показе из уже загруженного списка `groups` в `_GroupsBody` по
  id: переименование подхватится, удалённая группа просто скроет строку.
- Тест запущен из общего списка тестов (без группы) или сессия старая — строки
  группы нет.

## 7. Открытые вопросы

Нет. Решения по мелочам, которых нет в макете, приняты по умолчанию — если что-то
не так, поправь:

- на месте «Повторить ошибки» стоит «Пройти ещё раз» (tonal);
- вопрос, новый в тесте (не первое прохождение), выглядит как в первом прохождении
  («Знаю» / «Не знаю») и не попадает в «Исправил» / «Забыл»;
- в графике всегда 5 слотов: при 2–4 попытках пустые слоты слева;
- тап по всей карточке «Продолжить тест» продолжает тест, не только кнопка.
