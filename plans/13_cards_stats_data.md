> [15_group_detail_stats.md](15_group_detail_stats.md).

> со статистикой», «Группа — Kanji»).

## Решения

| # | Вопрос | Решение |
|---|---|---|
| 1 | Точность | Уже сделано: доля верных за последние 10 прохождений теста; у группы — среднее по тестам (`AccuracyCalculator`) |
| 2 | Где хранить агрегаты | Нигде. Всё считается при чтении из `cards` + `question_stats` + `test_attempts`, перенос теста между группами ничего не требует |
| 3 | Состояния вопроса | Новый / учится / освоен / слабый — по `question_stats`, пороги из профиля (`kMasteredThreshold = 3`, `kWeakThreshold = 0`) |
| 4 | «К повторению» | Не делаем: на главной выбран вариант «занимались N назад», а больше нигде этого чипа в макете нет. Заметки — в §3 |
| 5 | «Занимались N назад» | Последнее завершённое прохождение среди тестов (`test_attempts.completed_at`) |
| 6 | «Не начат» | По статистике: ни у одного вопроса нет показов. Не по точности — см. §4 |

## 1. Что требуется макету и откуда это берётся

| Элемент макета | Где | Источник | Синкается | Статус |
|---|---|---|---|---|
| Кольцо точности, % | группа, тест, сводка группы | `test_attempts` + `test_attempt_answers` | нет | ✅ есть (`accuracy` в entity) |
| «Отличная точность» (≥ 90%) | группа, тест | из точности | нет | ✅ тривиально |
| «N слабых» | группа, тест, сводка | `question_stats.streak < 0` | да | ✅ можно |
| «N новых» | группа, тест, сводка | карточка без строки статистики или `total_shown = 0` | да | ✅ можно |
| «Освоено» / «Учится» | сводка группы | `streak ≥ 3` / остальные показанные | да | ✅ можно |
| «N к повторению» | группа (вариант макета) | `last_shown_at` + активные дни | да | ⏸ не делаем (решение 4) |
| «занимались 2 дня назад» | главная, шапка группы | `MAX(test_attempts.completed_at)` | нет | ✅ можно |
| «Ещё не начат» / «Не начат» | группа, тест | все вопросы новые | да | ✅ можно |
| «Нет тестов» / «Нет вопросов» | группа, тест | `testCount` / `questionCount` | — | ✅ есть |

Резать по данным ничего не пришлось; «к повторению» убрано выбором варианта макета.

## 2. Состояния вопроса

Один вопрос — это уникальный `question_key` среди живых карточек. В группе одно
и то же слово из двух тестов считается один раз.

| Состояние | Условие | Пересечения |
|---|---|---|
| Новый | нет строки `question_stats` или `total_shown = 0` | — |
| Слабый | `streak < kWeakThreshold` (сейчас `< 0`) | — |
| Освоен | `streak ≥ kMasteredThreshold` (сейчас `≥ 3`) | — |
| Учится | остальные показанные | — |

В сумме дают в сумме число вопросов. Это нужно для сводки группы
(«Освоено 124 · Учится 40 · Слабые 16 · Новые 20»).

Статистика вопроса общая для всех тестов: ответ в тесте A меняет счётчики
теста B, если там есть то же слово.

## 3. «К повторению» — отложено

В этой задаче не делаем. Заметки на случай, если вернёмся.

У приложения нет интервального повторения с датами «повторить до», поэтому
«пора повторить» приходится определять самим. Варианты:

| Вариант | Условие | Плюсы | Минусы |
|---|---|---|---|
| **A. Давно не показывался** (рекомендую) | `activeDaysSinceLastShown ≥ 10` — тот же `decay_factor = 1`, что в подмешивании | Понятно пользователю; совпадает с логикой mixup | Активные дни берутся из `last_answered_at` (только последний ответ каждого вопроса), поэтому занижены — это уже так в mixup |
| B. Высокий score подмешивания | `score_no_noise ≥ порог` | Ровно то, что подмешает mixup | Порог не знаю, его надо подбирать по CSV; число непонятно пользователю |
| C. Слабые + давно не показывались | B ∪ «слабые» | Самая большая цифра | Дублирует чип «слабые» |

Стоимость A: `ScoringCalculator._activeDaysSinceLastShown` сделать публичным,
активные дни уже читаются (`QuestionStatsDatabase.getActiveDates`). Новых таблиц
не нужно.

## 4. Почему «не начат» считаем по статистике, а не по точности

В макете «не начат» = нет точности. Но точность локальная и не синкается, а
статистика синкается. На втором устройстве или после «Очистить историю
прохождений» тест с сотней ответов показывал бы «Не начат».

Поэтому:
- **не начат** — все вопросы новые;
- **кольцо** — только если есть точность. Если статистика есть, а точности нет,
  вместо кольца шеврон (как в макете для «не начат»), чипы показываем.

## 5. Модель

Новая entity `StudyProgressEntity` (freezed) — одна и та же для теста и группы:

```dart
StudyProgressEntity({
  required int newCount,
  required int learningCount,
  required int masteredCount,
  required int weakCount,
  double? accuracy,        // 0..1, null — нет прохождений
  DateTime? lastStudiedAt, // null — нет прохождений
})
  int get total => newCount + learningCount + masteredCount + weakCount;
  bool get isNotStarted => total > 0 && newCount == total;
  bool get isGreatAccuracy => (accuracy ?? 0) >= 0.9;
```

- В `TestEntity` и `TestGroupEntity` поле `accuracy` заменить на
  `StudyProgressEntity progress` (по умолчанию пустой).
- `questionCount` у теста оставить: это число карточек, а `progress.total` —
  уникальных вопросов. Обычно совпадают.

## 6. Расчёт

**DAO, по одному запросу на экран, без N+1:**
1. `CardsDatabase.getQuestionRows()` — по живым карточкам живых тестов:
   `test_id, question_key, streak, total_shown` (LEFT JOIN
   `question_stats`).
2. `TestAttemptsDatabase.getRecentAccuracy()` — уже есть.
3. `TestAttemptsDatabase.getLastCompletedAt()` — `MAX(completed_at)` по живым
   тестам: `test_id → DateTime`.
4. `GroupsDatabase.getAllEntries()` — все пары `group_id, test_id` одним
   запросом (сейчас `getTestIdsByGroupId` дёргается в цикле).

**Чистый калькулятор `StudyProgressCalculator`** (domain, без БД, как
`ProfileStatsCalculator`):
- `forTests(rows, accuracy, lastCompleted)` →
  `Map<testId, StudyProgressEntity>`;
- `forGroup(testIds, rows, ...)` → `StudyProgressEntity`: состояния по
  уникальным ключам, точность — `AccuracyCalculator.groupAccuracy`,
  `lastStudiedAt` — максимум по тестам.

Классификация в Dart, а не в SQL: пороги берутся из тех же констант, что в
профиле, и логика тестируется без БД.

## 7. Обновление экранов

`GroupsDatabase.watchGroupChanges` сейчас следит за группами, связями и
прохождениями. Добавить `cards` и `question_stats` через `tableUpdates`.

Риск: во время прохождения теста статистика пишется на каждый ответ, и список
групп в фоне будет пересчитываться (дебаунс 300 мс в блоке уже есть). На тысячах
карточек это несколько миллисекунд. Если окажется заметно, ставим
пересчёт на паузу, пока открыт экран прохождения.

## 9. Общие UI-компоненты (uikit, через скилл create-uikit)

Нужны и главной, и деталке группы. Сейчас в uikit нет ни чипа, ни
подходящего кольца с подписью внутри.

| Компонент | Что | Основа |
|---|---|---|
| `AppAccuracyRing` | кольцо точности с `NN%` в центре; размеры 48 / 64 / 88 | `AnimatedCircularProgress` (`lib/uikit/progress/`) уже оборачивает `M3EProgressIndicator.circular`; добавить `child` с процентом, толщину 5 / 7 |
| `AppStatChip` | плашка 28 px: иконка 16 + текст, обычная (фон 13%) и акцентная (фон 22%) | новый; повторяет «pill» из `_GroupListTile` |

**Цвет «чернил» карточки.** В макете кольцо и чипы рисуются цветом текста
своего контейнера (`onPrimaryContainer` и т. п.), трек — 18% того же цвета. В
монохроме и AMOLED контейнер серый, а кольцо и чипы берут акцент
(`--card-ink` в `m3.css`). Сейчас такого токена нет. Предлагаю добавить в
`AppColors` поле `cardInk` (`Color?`): `null` в цветном стиле — тогда берётся
цвет текста контейнера; `primary` в монохромных палитрах. Компоненты получают
`ink` и `onContainer` параметрами и про тему не знают.

Строки с плюрализацией (ARB ICU, как `groupsListTestCount`): «N слабых»,
«N новых», «Отличная точность», «Ещё не начат» / «Не
начат», «Нет тестов», «занимались {когда}», «Освоено / Учится / Слабые /
Новые». Для «сегодня / вчера / N дней назад» нужен новый форматтер по календарным
дням. `SyncTimeFormat` не подходит: он считает минуты и часы по серверным
часам, а после суток показывает абсолютную дату.
