# План: очистка истории прохождений в настройках и плашка с её размером

> Дата: 2026-10-03. Ветка: `design-fixes`. Продолжение
> [10_result_breakdown_and_resume.md](10_result_breakdown_and_resume.md).
> В макете Claude Design (`screens-settings.jsx`) такого блока нет: дизайн отстаёт
> от скоупа, поэтому вёрстка повторяет существующие карточки экрана настроек.

## Решения

| # | Вопрос | Решение |
|---|---|---|
| 1 | Название и место | «История прохождений» — отдельная карточка в настройках |
| 2 | `VACUUM` после очистки | Делаем |
| 3 | Что показывать | Только размер, без числа прохождений |
| 4 | Объём очистки | Только всё целиком, без очистки по тесту |

## 1. Что очищаем

Только историю прохождений — две таблицы из плана 10:

| Таблица | Что лежит | Объём (замер) |
|---|---|---|
| `test_attempts` | строка на каждое завершённое прохождение | ~0,23 КБ на прохождение, без предела |
| `test_attempt_answers` | ответы только последних 5 прохождений каждого теста | ~0,18 КБ на ответ; не больше 5 × число карточек на тест |

С ограничением из плана 10 история не разрастается. Пример: 100 тестов по
25 карточек дают около 2,3 МБ ответов. К этому добавляется около 1 МБ строк
прохождений за год активного использования.

**Не трогаем:** тесты и карточки, статистику по вопросам (`question_stats`),
журнал ответов для синка (`answer_events_outbox`), активную сессию («Продолжить
тест»), настройки.

Что увидит пользователь после очистки:
- у каждого теста следующее прохождение снова «первое» — без дельты, графика
  и трендов;
- счётчик «N из M» начинается с нуля.

Это не кэш. Системная «Очистить кэш» на Android эти таблицы не трогает, а наша
очистка стирает данные без возможности восстановления. Поэтому в интерфейсе
блок называется «История прохождений».

## 2. Флоу

```
Настройки → карточка «История прохождений»
  ├─ при открытии экрана считается размер (вместо числа — скелетон)
  ├─ «Занимает 1,2 МБ»                         [Очистить]
  │      └─ тап → диалог подтверждения
  │            «Очистить историю прохождений?»
  │            «Графики и динамика по вопросам начнутся заново.
  │             Статистика, тесты и карточки останутся.»
  │            [Отмена] [Очистить]
  │                └─ в кнопке прогресс → таблицы пустеют → VACUUM →
  │                   размер пересчитан → снек «История очищена»
  └─ истории нет: «Пусто», кнопка недоступна
```

- Подтверждение обязательно: действие необратимое, синка у истории нет.
- Пока идёт очистка, кнопка показывает прогресс и повторно не нажимается.
- Если очистка упала (не должна, но `makeCall` ошибку поймает) — снек «Не
  удалось очистить историю» и пересчёт размера.

## 3. Данные

### 3.1. Размер

`dbstat` — виртуальная таблица SQLite со страницами каждой таблицы и индекса.
`package:sqlite3` 3.1.5 по умолчанию поставляет свою сборку SQLite с
`SQLITE_ENABLE_DBSTAT_VTAB` (см. `doc/hook.md` пакета). Переопределений сборки
в приложении нет, значит, на устройствах `dbstat` доступен.

```sql
SELECT SUM(pgsize) FROM dbstat WHERE name IN (
  'test_attempts', 'sqlite_autoindex_test_attempts_1', 'idx_test_attempts_test',
  'test_attempt_answers', 'idx_test_attempt_answers_attempt'
)
```

Запрос считает реально занятые страницы, поэтому после удаления число сразу
падает, даже если файл ещё не ужат.

**Фолбэк**, если `dbstat` недоступен (запрос бросит `no such table`): оценка по
числу строк × средний размер из замеров (0,23 КБ и 0,18 КБ). В UI тогда «≈ 1,2 МБ».

### 3.2. Очистка

1. `DELETE FROM test_attempt_answers; DELETE FROM test_attempts;` в одной транзакции.
2. После транзакции — `VACUUM`. Без него файл БД не уменьшится: освобождённые
   страницы только переиспользуются при следующих записях. `VACUUM` переписывает
   всю базу. При нынешних объёмах (единицы МБ) это доли секунды; на время
   операции нужно ещё столько же свободного места.

### 3.3. Слои

- DAO `TestAttemptsDatabase`: `historySizeBytes()` через `dbstat`, `countRows()`
  обеих таблиц для фолбэка, `clearAll()`.
- `AppDatabase`: `vacuum()` — `customStatement('VACUUM')` вне транзакции.
- Entity `AttemptHistoryUsage` (freezed): `bytes`, `isEstimate`.
- `ITestAttemptRepository`: `getHistoryUsage()`, `clearHistory()` — удаление и
  `VACUUM`, возвращает новый размер.

## 4. Bloc

Отдельный `AttemptHistoryBloc` в фиче `test_execution`. Создаётся в
`SettingsFlow` — сейчас этот флоу ничего не провайдит. В `SettingsBloc` его не
кладём: тот живёт в app-скоупе и читается темой приложения, тянуть туда работу
с БД незачем.

- События: `started` (посчитать размер), `clearRequested`.
- Состояние: `loading` → `loaded(usage, isClearing)`. Одноразовый результат
  очистки — `SideEffectValue`, как у экспорта статистики; по нему показывается снек.
- Размер пересчитывается при открытии экрана и после очистки. Живое обновление
  не нужно: пока открыты настройки, новые прохождения не пишутся.

## 5. UI

Новая `_SettingsCard` «История прохождений» (иконка `history`) между карточкой
«Карточки» и экспортом статистики:

| Состояние | Строка | Кнопка |
|---|---|---|
| загрузка | скелетон вместо размера (`uikit/skeleton`) | недоступна |
| есть данные | «Занимает 1,2 МБ» (при фолбэке — «≈ 1,2 МБ») | `FilledButton.tonal` «Очистить» |
| пусто | «Пусто» | недоступна |
| очистка | прежний размер | прогресс в кнопке, как у экспорта |

- Под строкой — пояснение мелким текстом: «Прохождения тестов для графиков и
  динамики на экране результата».
- Размер форматируется по локали: `0 Б`, `850 КБ`, `1,2 МБ` / `850 KB`, `1.2 MB`.
  Число — через `NumberFormat` из `intl`, единицы — в ARB.
- Подтверждение — `AppDialog.confirm`, снек — `SnackController`, как у экспорта.
- Строки — новый сегмент `@segmentSettingsHistory` через `/localize`. Остальной
  экран настроек частично на хардкоде; его не трогаем, это отдельная задача.

## 6. Тесты

- **DAO и репозиторий на файловой БД:**
  - после записей размер больше нуля;
  - после очистки обе таблицы пусты, размер 0, файл после `VACUUM` уменьшился;
  - тесты, карточки, `question_stats`, `active_sessions` и outbox не тронуты.
- **Bloc:**
  - `started` → `loaded`;
  - `clearRequested` → `isClearing` → `loaded(0)` и результат для снека;
  - повторный `clearRequested` во время очистки игнорируется.
- **Локализация** (по образцу `test/l10n/attempt_results_l10n_test.dart`):
  форматирование размеров 0 / 999 Б / 1 КБ / 850 КБ / 1,2 МБ / 12 МБ на ru и en,
  вариант «≈».
- **Голдены карточки:** загрузка, с данными, пусто, очистка.
